Remote command path

OcExecutor invokes oc exec … /bin/sh -c. With no pod_name, diagnostics hit the baseline pod. A candidate pod_name creates a temporary executor for that pod.

SSH mode implements the same RemoteExecutor interface.

Local benchmark path

PodManager exists only when OpenShift mode has a pod template.

Provisioning details

A completed downloader Job is reused. The generated experiment Pod manifest is written to a local template file. Baseline service port-forwarding allocates an available local port.

Boundary of the invariant

Profile provisioning may reconcile the baseline Deployment before tuning. Once AgenticRunner.run() begins, experiments use separate Pods; the runner's baseline path is for reads and benchmarks.

A profile's max_tensor_parallel_size is passed into the agent context. The example profile selects its benchmark workload; the system prompt still explicitly requests a balanced baseline and candidate run.

Runner internals · model response cycle

An iteration counts a model call, not an experiment

while not state.done and iteration < max_iterations:
    iteration += 1
    response = messages.create(
        system=SYSTEM_PROMPT,
        tools=TOOL_DEFINITIONS,
        messages=messages
    )
    if response.stop_reason == "tool_use":
        dispatch_each_tool_block(response)
    elif response.stop_reason == "end_turn":
        append_text_and_continue_prompt()

State and replay data

AgentState stores baseline/current benchmark text by profile, actions, kernel analysis, done, success, and summary.

Each dispatched tool records iteration, arguments, timestamp, and at most 4,000 output characters in decision_log. Up to 8,000 output characters return to the model.

run_benchmark sets the runner's “benchmark called” flag even if the benchmark fails.

At the fourth model iteration without a benchmark call, the runner injects a benchmark reminder. With five iterations left, it injects a request to call done.

Comparison · concrete semantics

Comparison operates on shared concurrency records and numeric fields

Flatten GuideLLM JSON

_extract_flat_metrics reads benchmarks[].config.strategy.max_concurrency (or worker count), request totals, throughput, TTFT, ITL, TPOT, request latency, and request rate. It extracts mean, median, P50, P95, P99 where present.

Baseline and current records are aligned by common concurrency. With no common point, the comparator falls back to the first record from each file.

2% threshold per metric

percent_change = 100 × (current - baseline)
                 / baseline

throughput: +>2% improvement
latency:    ->2% improvement
within ±2%: neutral

detect_regression returns per-metric regressions, improvements, neutral results, and a per-concurrency verdict.

Current code compares every common numeric field, including request counts and duration. Unknown field names default to “higher is better.” The deck does not treat the verdict as a validated service-level objective or statistical significance test.

Recipes and merged PRs supply candidate hypotheses

vLLM Recipes: model configuration path

Prompt sequence: fetch recipes.vllm.ai/models.json, match the served HF ID, then fetch model JSON. It reads model.base_args, variants and quantization args, hardware overrides, features, and opt-in features.

If there is no exact match, the prompt directs a family/architecture YAML search in vllm-project/recipes. Network failure falls back to local practices.

Merged PR index: local change history

pr-index sync builds SQLite FTS5 from merged PR title, body, labels, and optionally changed-file names. Derived facets cover hardware, architecture, and tuning domains.

search_vllm_prs(query, architecture, hardware) searches the local DB. Its manifest records repository, schema version, document count, and generation time; the checked-in manifest currently lists 4,266 documents.

Termination · report artifacts

The hard boundary is model-call count; final output is Markdown + JSON

Stopping logic

done sets AgentState.done, success, and summary. The prompt asks for 10 consecutive experiments without a >2% improvement before calling it; the runner does not maintain that counter.

max_iterations is enforced in the loop. If reached without done, the runner constructs a fallback summary from benchmark and comparison entries in decision_log.

Persisted results

Reporter.generate writes agent_reports/report_<timestamp>.md and .json. The report includes baseline/final metrics, actions, bottlenecks, optional kernel analysis, token usage, and decision log.

The CLI parses retained benchmark text into report snapshots. Candidate Pods are cleaned up in finally before report generation.

The current runner depends on the agent to follow benchmark/log/cleanup ordering and to select the best configuration. These are prompt rules, not enforced transitions in the Python loop.
