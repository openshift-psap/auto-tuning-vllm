# vLLM merged pull-request index

`auto-tune-vllm pr-index` builds a local SQLite FTS5 index of merged pull
requests from `vllm-project/vllm`. It is intended to be generated by one
maintainer or a scheduled job, committed as a Git LFS artifact, and queried
locally by developers and the tuning agent.

## Maintainer workflow

Use a read-only `GITHUB_TOKEN` to avoid unauthenticated API rate limits:

```bash
export GITHUB_TOKEN=github_pat_...
auto-tune-vllm pr-index sync
git lfs track data/vllm-pr-index.sqlite
git add .gitattributes data/vllm-pr-index.sqlite data/vllm-pr-index.manifest.json
```

For the first full-history import, use `--metadata-only` to index PR titles,
descriptions, labels, and derived facets in one paginated API pass. This avoids
one additional API request per PR. A later normal sync enriches newly seen PRs
with changed-file names.

The sync command writes a reviewable manifest beside the database with the
source repository, schema version, document count, and generation time. The
database is ignored by default so a generated copy is only committed
intentionally; use `git add -f` for the LFS artifact.

Only one job should update the database: SQLite binaries are generated
artifacts and cannot be merged meaningfully.

## Search

After `git lfs pull` materializes the database, searches do not contact
GitHub:

```bash
auto-tune-vllm pr-index search "KV cache decode latency" --hardware h100
auto-tune-vllm pr-index search "expert parallelism" --architecture moe --json
```

The index stores merged PR titles, descriptions, labels, changed-file names,
and derived architecture, hardware, and tuning-domain facets. It does not
currently index review comments or full patch contents.
